## 设计决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 自动保存守卫位置 | useEffect async wrapper（不修改 saveManager） | saveManager 的同步读缓存契约被多处依赖；async wrapper 零破坏 |
| 计量条位置 | 档案面板 header 下方、列表上方 | 面板级元信息，用户先看容量再浏览条目 |
| 计量范围 | keeper_game_saves + keeper_api_settings | 完整性（api_settings 体量极小但计入） |
| 容量公式 | `used + estimate > quota * 0.95` 拒绝 | 导入 `file.size*2`（UTF-16 膨胀估计），保存 `Blob.size`；95% 留余量 |
| 降级策略 | estimateSaveStorage 失败放行 | 估算失败不能阻塞用户正常操作 |

## 仍需继续验证 / 已知问题
- 自动保存 `estimateSaveStorage` 每次 effect 触发都读 2 次 IDB `getItem`（keeper_game_saves + keeper_api_settings），对高频状态变更（打字、线索等）可能有轻微性能开销。当前数据量（<100MB）下可忽略，后续若需优化可加内存缓存（如 2s 内复用上次查询值）。
- `new Blob([str]).size` 返回 UTF-8 字节数，但 IDB 内部以 UTF-16 存储 JavaScript 字符串，实际占用可能略高。95% 守卫有余量覆盖此差异，参考 NyaaChat 已验证模式。
- 导入容量检查中 `file.size * 2` 是保守估计，实际膨胀系数取决于 JSON 内容（纯 ASCII 约 2x，中文约 0.67x）。保守值不会导致误放行。
- P1 的 IDB 迁移在浏览器实际环境中尚未端到端测试；P2 新增功能同样需要 rebuild + 浏览器验证。
